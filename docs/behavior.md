# Retained behavior and owner authority

The controller, core validator and assembly layer retain their existing decision,
receipt, order, recovery and position-management behavior. Distribution changes make
deployment identity explicit and provide a new-instance bootstrap. They do not turn
analysis into authority or replace the strategy.

The existing entry workflow compares contract-specific estimated probabilities for
option premium resale, with an owner-controlled minimum (initially 40%). An exact tie
stays out; a blocked winner does not authorize a substitute. The existing 120-second
configured cadence is a research cadence, not a profitability claim or sale deadline.
These estimates are supplied by an analyst; the controller does not establish their
calibration or predictive value.

Owner controls include limits, entry/management windows, manual-control holdings,
scheduled closing and session arming. Scheduled closing is initially disabled. If an
owner explicitly enables it, the retained workflow can close managed holdings at a loss;
it does not guarantee a fill by a deadline. Automatic profit-management behavior and
scheduled closing have different authorization conditions. Read the dashboard's actual
saved settings before describing what the instance may do.

All of these must be distinguished: provider consent, an accepted contribution,
candidate eligibility, controller readiness, host writes enabled, owner ARM, broker
acceptance, and confirmed fill. A new process disarms, and the owner's fresh action is
needed to enable execution. No installation command arms or enables candidate execution.

Market-calendar data and provider contracts are retained from the working project.
They are versioned software assumptions; do not claim perpetual calendar coverage or
future broker compatibility. Validate updates independently before relying on execution.
